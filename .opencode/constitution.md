## Purpose

Talk-to-text that works even when the internet does not. Offline-first voice
dictation for Linux (Hyprland) plus Windows. Local STT by default, optional
free-tier cloud (Groq, NVIDIA NIM) when online. Current milestone is v0.0.1
Hello voice: Hyprland keybind triggers capture, whisper.cpp base.en on CPU,
raw clipboard paste, no UI, no persistence. Prove capture-to-injection end
to end before cloud providers or UI land.

## Constraints

- `core/` never imports a platform crate (no cpal, tauri, winapi, nix,
  ydotool bindings). Platform code lives in `adapters-*`. Core defines
  behaviour only.
- Local is the guarantee, not the fallback. Cloud chain degrades to local
  CPU, never the reverse.
- Every side effect is gated by a session-keyed ticket (TicketRegistry).
  Retries, replays, and double-triggered hotkeys never duplicate an effect.
- Conventional commits for versioning (`feat(core): ...`, `fix(linux): ...`).
- Copy tone: sentence case, no exclamation points. Errors state what
  happened and what to do next.
- Windows adapters stay stubs until v0.6.0. Do not leak platform
  assumptions into `core/`. CI runs Windows from day one to catch it.

## Prove it works

Done means: fmt clean, clippy clean with warnings denied, full workspace
tests green, hardware-free e2e proof green. Real-device loop verified by
hand with `susurro doctor` plus `listen --mock` before `listen` on hardware.

### Run

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- `cargo run -p susurro-cli -- doctor`
- `cargo run -p susurro-cli -- listen --mock --stdout`

### Prove

- `cargo fmt --all -- --check` exits 0 with no diff
- `cargo clippy --workspace --all-targets -- -D warnings` exits 0
- `cargo test --workspace` exits 0, including
  `mock_e2e_injects_transcript_once` and
  `double_hotkey_cannot_double_inject` in `cli/tests/e2e_mock.rs`
- `susurro doctor` reports mic, tools, and model as found on a real machine

### Gotchas

- Real loop needs `whisper-cli`, a `base.en` model (`SUSURRO_MODEL` or
  `~/.local/share/susurro/models/base.en.bin`), `wl-clipboard`, `ydotool`
  with `ydotoold` running, and `socat`. CI uses mocks and never has these.
- Linux builds need `libasound2-dev` and `pkg-config`. Tauri check needs
  `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf` plus
  `npm ci && npm run build` in `app-tauri/`.
- `app-tauri/src-tauri` is excluded from the Cargo workspace. Workspace
  commands never build it. Its backend lints separately.
- No `.env` flow in this repo. Model path comes from env var
  `SUSURRO_MODEL`, not a dotenv file. `/wizard` has nothing to generate
  until cloud keys land in v0.3.0.
- Windows runners run from day one with stub adapters. A Windows-only
  failure is a real finding, not a runner flake.

## Boundaries

- Validation happens at the edges: CLI arg parsing (`cli/src/main.rs`),
  adapter constructors (audio device, model path, socket path), and config
  reads. Core trusts values once they cross the port trait.
- Port traits live in `core/src/ports.rs`. Errors narrow to
  `core/src/error.rs` (`CoreError`). No adapter error type leaks into core.
- Secrets (future cloud keys) belong in the OS keyring, never plaintext,
  per the plan. Nothing in the repo reads keys from files today.

## Domain

- States in `core/src/state.rs`: Idle, Listening, Transcribing, Cleanup,
  Injecting.
- Identity in `core/src/session.rs`: SessionId, Ticket, TicketRegistry.
  Pipeline takes one ticket per session and rejects replays.
- Orchestration in `core/src/pipeline.rs`: `Pipeline::run_once` runs
  capture, STT, cleanup, injection in order.
- Ports in `core/src/ports.rs`: AudioCapturePort,
  VoiceActivityDetectorPort, SpeechToTextPort, TextPostProcessorPort,
  TextInjectionPort, GlobalHotkeyPort, OverlayRendererPort,
  SettingsStorePort, HistoryStorePort, NetworkStatusPort.
- Adapters today: real audio capture plus mock, whisper.cpp binary plus
  mock, passthrough cleanup, Hyprland socket plus wl-copy/ydotool paste
  plus mock injector. Cloud, VAD, storage, and Windows adapters are stubs
  sequenced by milestone.
